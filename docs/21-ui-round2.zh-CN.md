# 控制台第二轮 UI / UX 优化

本轮按照第二轮优化清单的 R1–R14 顺序实施，每步独立提交。沿用现有靛蓝主色、
浅色 / 深色 / 护眼主题、12px 最小字号和 75% / 90% 进度阈值。

## 与清单示例的差异

- 开始实施时 GitHub 和部署的前端已经包含资产与出口页面，清单关于源码缺失的判断已过时。
- 现有等宽 token 是 `--hf-mono`；`--hf-data` 已指向正文字体，因此技术字段使用前者。
- 出口操作遵循全局“同一行有两个以上操作时全部用 IconAction”规范，解决清单局部示例混用文字与图标的冲突。
- `operation_invalid` 只有在原始原因明确为不支持操作类型时提示升级 Agent；其他无效参数不误报为版本问题。
- Agent 协议未提供完整操作能力声明，未通过猜测版本号来禁用按钮。
- 可选的登录卡片化和报表曲线平滑保留现状。节点性能图保留原始折线。
- 原有 Ctrl / Cmd + K 导航继续可用，桌面触发器补充搜索范围文字。
- 表头在自身滚动容器内吸顶，使用 `top: 0`，避免再次叠加外部顶栏高度。

## 必要验证

按项目维护者要求，省去无关全量测试及重复截图矩阵。

- Go：订阅计数回归用例、Operations Layer API 用例通过。
- 前端：TypeScript 检查、生产构建通过。保留构建器已有的大分块提示。
- 23 个针对性前端用例通过，覆盖错误解释 / 历史折叠、节点运维、订阅调整 / 错误重试、
  通知编辑 / 凭据保留、报表无基数对比、导航与用户抽屉。
- 浏览器覆盖登录及九个管理视图，分配到浅色、深色、护眼与 1440 / 1024 / 390px 场景；
  重点核对窄屏卡片、五个图表刻度、用户抽屉模式 / 底部操作、危险按钮与 Tooltip。
- 登录 autofill 用 Chromium 强制伪状态验证三套主题的实际计算样式，未向密码管理器保存登录信息。
- 小于 12px 的显式字号、清单列出的旧绿色、危险 quaternary 图标按钮扫描无匹配。
- 线上验证仅查看数据；测试中的通知发送、配置变更使用 mock，未向真实通道发送测试消息。

## 部署与回滚

R1 是服务端查询修复，发布需同时更新控制台服务和前端资源。更新前应保留旧服务二进制、
一致性数据库备份和前端 release；新二进制先验证配置及备份，再重启控制台服务，健康检查
通过后切换静态资源软链接。此轮不包含数据库迁移、Agent 或代理核心更新。

失败时恢复旧二进制与前端软链接。正常回滚无需恢复数据库，避免丢失更新期间的新流量记录。
具体部署路径、哈希与备份位置记录在维护者本地运维记录中，不包含在公开仓库。
